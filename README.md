# Unreliability or Disagreement? What an Interpercentile Decomposition Can and Cannot Show

Code and data for the paper by Pavan Kumar Dubasi (Independent researcher).

Accepted as a poster at the NeurIPS 2026 Workshop "Can We Trust AI Evaluation? Robustness, Causality, and Risk in Modern AI Assessment" (TAE). The workshop is non-archival.

OpenReview: https://openreview.net/forum?id=esMA3Bmav8

## Summary

Laban et al. (2025, arXiv:2505.06120) report that LLMs "get lost" in multi-turn conversation and decompose the drop into a small loss of aptitude (a high percentile of per-instruction scores) and a large rise in unreliability (an interpercentile range). This paper shows what that decomposition can and cannot support. The two components are one reparameterisation of a percentile pair; with binary scorers the unreliability term is a disagreement rate that vanishes when a model fails consistently; and its sign is forced whenever the single-turn baseline is saturated. A null with no reliability parameter over-produces the reported rise in unreliability. On a fresh, frozen corpus of 7,048 conversations (three tasks with programmatic scorers, seven model families via AWS Bedrock) the degradation reproduces in every cell, but an operational oracle-retry test separates mathematics (loss is recoverable) from function calling (a median 20% of instructions fail deterministically), which the decomposition cannot do.

## Repository layout

    analyze_repro.py            main analysis: P / A90 / U90_10 per cell + percentile-convention sweep
    analyze_metric.py           Figure 1: step functions, E[U|p], task-blind binomial null (Spearman rho)
    analyze_ceiling.py          saturation vs margin check (supporting)
    analyze_recoverability.py   Table 2: oracle best-of-K retry, unrecoverable gap, deterministic failures
    verify_theorem.py           Beta-Bernoulli null with no reliability parameter (Sec. 4)
    verify_objections.py        relative vs absolute form, floor effect, binarised BLEU
    verify_confounds.py         metric-identity check and common-N subsampling control
    fig_combined.py, fig_multitask.py   supplementary figures (not in the paper PDF)
    paper_tables.py             prints Table 1 and Table 2 from the JSON results
    viz_style.py                shared plotting style
    *_results*.json             results as produced from the frozen corpus
    repo/logs_run1_frozen/      FROZEN corpus: 42 JSONL files, 7,048 records, 6,794 scored
    harness_overlay/            our changes to the upstream Laban et al. harness (Bedrock adapter, instruction subsets)
    scripts/setup_harness.sh    fetches the upstream harness at the pinned commit and applies the overlay
    figures/figM1_metric.pdf    Figure 1 as it appears in the paper
    paper/                      submitted (anonymous, review) version: PDF + LaTeX source

## Reproduce the paper (offline, no API calls, no cost)

Run from the repository root. Set `MPLBACKEND=Agg` on a headless machine.

| Paper element | Command | Output |
|---|---|---|
| Sec. 3 corpus counts, per-cell decomposition, power gates | `python analyze_repro.py logs_run1_frozen` | `repro_results_bymodel.json`, `repro_results_*.json`, per-cell `figR1_*` sweeps |
| Table 1 | `python analyze_repro.py logs_run1_frozen` then `python paper_tables.py` | stdout |
| Figure 1 (a)-(c), Spearman rho = 0.66, per-task medians | `python analyze_metric.py` | `figM1_metric.pdf`, `metric_results.json` |
| Table 2, retry paragraph (91.8%, 47.8%, 23.8 pp, 20.0%) | `python analyze_recoverability.py` then `python paper_tables.py` | `recoverability_results.json` |
| Null with no reliability parameter (+167% to +196%, -0.2% to -6.9%) | `python verify_theorem.py` | stdout |
| Relative vs absolute form (14 of 16 vs 10 of 16) | `python verify_objections.py` | stdout, `figR5_floor_effect.pdf` |
| Run-count control | `python verify_confounds.py` | stdout |
| Saturation check | `python analyze_ceiling.py` | `ceiling_results.json`, `figR4_ceiling_degeneracy.pdf` |

Every shipped `*.json` result is regenerated byte-for-byte by these commands, and the regenerated `figM1_metric.png` is pixel-identical to the paper's figure.

## Data

`repo/logs_run1_frozen/{math,actions,data2text}/{full,sharded}/*.jsonl`, one JSON object per line:

    {"conv_id", "conv_type": "full" | "sharded", "task", "task_id", "dataset_fn",
     "assistant_model", "system_model", "user_model", "git_version", "trace", "is_correct", "score"}

- `conv_type` `full` is single-turn, `sharded` is multi-turn. `score` is in [0, 1].
- 254 of 7,048 records have `score: null` (generation failures) and are excluded; one record (`math/full/full_math_deepseek-r1.jsonl`, line 42) is truncated JSON and is skipped.
- A cell is analysed only with at least 10 instructions paired across both conditions and a median of at least 4 runs per instruction per condition; 5 of 21 cells fail and are listed as skipped.
- `git_version` is the upstream harness commit (`c865793`).
- One model-hallucinated email address inside a Pixtral function-call argument was replaced with `[email-redacted]`; no score or analysed field changed.
- `palmyra-x5` logs are present but excluded by the power gates.

## Regenerating the conversations (paid)

The harness is Microsoft's `lost_in_conversation` (MIT). We do not vendor it; `scripts/setup_harness.sh` clones it at the commit we used and applies `harness_overlay/` (a Bedrock adapter, a 7-line switch in `model_openai.py`, and the three instruction subsets we ran).

    bash scripts/setup_harness.sh          # creates ./harness
    cd harness
    export AWS_REGION=us-east-1             # use your own AWS credentials via the boto3 chain

    # mathematics (30 instructions)
    USE_BEDROCK=1 python run_simulations.py \
      --dataset_file data/sharded_math30.json --tasks math \
      --models llama4-maverick qwen3-32b deepseek-r1 claude-sonnet4.5 nova2-lite \
      --system_model llama4-maverick --user_model llama4-maverick \
      --N_full_runs 6 --N_sharded_runs 6 --N_concat_runs 0 \
      --N_workers 8 --log_folder logs_run1

    # function calling (25 instructions)
    USE_BEDROCK=1 python run_simulations.py \
      --dataset_file data/sharded_actions25.json --tasks actions \
      --models llama4-maverick qwen3-32b deepseek-r1 llama3.3-70b claude-sonnet4.5 nova2-lite mistral-pixtral-l \
      --system_model llama4-maverick --user_model llama4-maverick \
      --N_full_runs 6 --N_sharded_runs 6 --N_concat_runs 0 \
      --N_workers 8 --log_folder logs_run1

    # data-to-text (25 instructions)
    USE_BEDROCK=1 python run_simulations.py \
      --dataset_file data/sharded_data2text25.json --tasks data2text \
      --models llama4-maverick qwen3-32b deepseek-r1 llama3.3-70b \
      --system_model llama4-maverick --user_model llama4-maverick \
      --N_full_runs 6 --N_sharded_runs 6 --N_concat_runs 0 \
      --N_workers 6 --log_folder logs_run1

Pass `--system_model` and `--user_model` explicitly: their upstream defaults are `gpt-4o-mini`, and the Bedrock adapter silently maps any OpenAI-style id to `llama4-maverick`. Install the upstream `requirements.txt` plus `boto3` for this step. Model aliases are in `harness_overlay/model_bedrock.py`. A fresh run samples new conversations and will not match the frozen corpus record for record.
